# Ver.4.3.0 — 距離に応じた行軍と到着時の戦闘

## 対象と時間

129城の地理座標を共有する `travel.js` で、出陣元と目的地の距離を計算する。基本時間は `ceil(15 + distanceKm * 0.5)` 秒。支拠点には親城から方角に応じた局地的な位置差を適用する。遠距離だけを一定秒数へ切り詰める上限は設けない。

| 出陣 | 保存先 | 時間基準 |
| --- | --- | --- |
| 天下地図の手動出陣・軍師AI、野良兵戦 | 未接続時はセーブ、接続時は `battle_marches` | 共通世界時計の `elapsedMs` |
| 共通フィールドの本拠・支拠点、同盟集結軍 | `battle_marches` | 共通世界時計の `elapsedMs` |
| 偵察・駐留部隊の派遣 | 私有の派遣状態と操作台帳 | 共通世界時計の `elapsedMs` |
| 共有天下統一の攻撃 | `conquest_marches` | サーバー実時間 |

共通時間の停止・速度変更は通常の行軍にも適用する。共有天下統一は独立した実時間の大会。すでに現地に駐留している部隊の反撃、期間限定合戦のステージ戦、月次の環境CPU戦は既存の戦闘方式を維持する。

## 出陣から到着まで

出陣時は全出陣兵・兵糧・指令を確保し、行軍ID、出陣元、目的地、到着時刻、出陣時の戦力と乱数を保存する。敵への損害、占領、戦功、報酬は到着前に発生しない。同じ操作番号の再送は同じ行軍または確定済みの結果を返す。

到着時は現在の出陣資格・所属・攻撃先の物語と領有・保護・出陣元を再確認する。資格や対象が変わり実行できない行軍は中止し、預かった兵と費用を返す。通常の主力軍は1人1隊。共有天下統一も同一領主の行軍は1隊で、最初の足場を得るまでは同盟の先発隊の到着を待つ。足場を得た後は、同盟の待機兵・物資とクールダウンの範囲で別の同盟員も出陣できる。

行軍の確定、保存の更新、占領、報酬は行軍状態と関係する版番号を条件にした原子的な処理で行う。行軍中の兵を消す古いセーブは受け入れない。未接続の行軍を初めて同期するときは、時間基準を固定し、すでに確保済みの兵を再徴収せずサーバー台帳へ移す。クライアントはサーバー管理の行軍を自分で戦闘・返還しない。

同盟集結軍は参加者の預託兵を到着まで固定する。共有天下統一の返還先が所持上限に達した場合は、受け取れなかった兵・物資を行軍台帳へ残す。空き容量のある返還先だけを先に選ぶことで、古い満杯の金庫が後続の返還を妨げない。

## APIと画面

- `POST /api/v1/marches/campaign`：天下地図の出陣を受け付ける。`kind,targetId,tactic,troops,campaignId,requestId,deviceId,expectedRevision` を送る。
- `GET /api/v1/marches?deviceId=...`：本人に関係する行軍・到着履歴と同期情報を取得し、期限を迎えた行軍を確定する。
- 既存の `/field/attack`、`/roaming/battle`、`/alliance/rally/launch`、`/covert/dispatch`、`/conquest/action` も、即時の戦果と受付済みの行軍を区別する。

共通の行軍情報は `id,requestId,kind,status,timeBasis,sourceCastleId,targetCastleId,distanceKm,durationMs,departedAtMs,arrivesAtMs,remainingMs,troops`。`status` は `marching`、`resolved`、`cancelled`。確定後は戦果または中止理由を付ける。各既存経路の `accepted` の互換値だけに依存せず、行軍ID・操作番号・状態を検証する。

出陣画面に距離と所要時間を表示し、共通の「進軍と戦果」で残り時間と結果を確認できる。秒ごとの更新はカウントダウンの文字だけを変更し、入力やフォーカスを奪わない。通信上の未確認操作と、受理済みの行軍は別に管理する。到着済み・中止済みの再確認でも、保存の版を同期してから未確認操作を解消する。

## 到着処理の起動

状態取得・同期・通常のAPIアクセスから、件数を制限した到着処理を起動する。Workerの `scheduled` ハンドラーにも同じ処理があるが、今回の配備ソースに新しいcron設定は追加しない。全員が接続を閉じている間も到着期限は保存され、次のサーバー処理で反映される。外部スケジューラーの実行時刻を前提にした厳密な通知・反映時刻は保証しない。

共有天下統一は、大会終了より前に到着する攻撃だけを受け付ける。大会終了後の遅い処理でも、受理済みの到着を先に確定し、未確定の行軍がある間は最終順位を固定しない。

## 配備と検証

`0027_battle_marches.sql`、`0028_conquest_marches.sql` と移行ジャーナルを同じリリースに含める。ブラウザの `travel.js` と `engine.js`、Workerの `travel.js` と `game-engine.js` は同一の実装を使用する。`travel.js` をエンジンより前、`travel-ui.js` を各戦闘画面より前に読み込み、Service Workerのキャッシュにも含める。

APIの配備確認は `/api/v1/health` の `version: "4.3.0"`、`features.attackTravel: true`、`status: "ready"`。移行が未適用なら正常扱いにしない。

主な検証は `tests/test-travel-engine.cjs`、`tests/test-travel-ui.cjs`、ブラウザの同期橋の検証、Workerの `scripts/test-battle-travel.mjs` と `scripts/test-conquest-travel.mjs`。近距離と遠距離、到着境界、保存と再開、同期切り替え、二重送信、同時到着、出陣資格変更、資産の上限と返還、大会の締切を検証する。既存の同期・周回・支拠点・幕府開設の検証も継続する。実際の領主に対する攻撃や公開イベント作成はテストに使わない。
