## 変更と使い方

### 完成・到着をまとめる「行動予定表」

城下町の「領国の指揮台」とゲーム内メニューから「行動予定表」を開ける。普請・研究・進軍・派遣・帰還を、現在の速度での完成・到着が近い順に表示する。本拠の指揮台は件数と直近2件を示し、詳細な一覧は予定表で確認する。

「すべて」「普請」「研究」「進軍・派遣」「帰還」で絞り込み、城・施設・研究の名前でも探せる。施設管理の入口では普請に絞って開く。予約普請は完成までに加えて着工待ち時間を表示し、予定ごとのボタンから施設・研究・地図・部隊の既存画面へ進める。長い一覧は40件ずつ表示する。

共通時間で進む予定は1倍・2倍・4倍速と停止に連動する。停止中は完成時刻を約束せず、実時間で進む移動は別に計算する。残り時間が0になっても表示側では完了を作らず、「完成を確認中」「到着を確認中」「帰還を確認中」とする。到着確定・戦闘・報酬・兵の受取は既存のエンジンとサーバーが扱う。

一覧の更新では検索語、絞り込み、入力の選択範囲、フォーカス、スクロール位置を保持する。閉じると既存の移動更新への購読を解放し、起動元へフォーカスを戻す。アカウント・利用状態・戦役が切り替わった場合も次の既存更新で閉じる。閉じるイベントが遅れて届いても、開き直した画面の購読を解除しない。

### 本人の同盟援軍・集結移動を統合

同盟作戦で取得した本人の援軍・集結地点への往復も予定表へ加える。認証済みの既存応答から本人所有の移動だけを取り出す仕組みで、予定表用の追加API取得やポーリングは行わない。他領主の私的な部隊情報は追加しない。

同盟部隊には最終取得時刻と取得済み情報である旨を表示する。未取得・権限失効時は未取得などの案内を示し、「同盟作戦で確認」へ進める。移動の変更・到着結果は同盟作戦で再確認する。取得済み一覧を閲覧しただけでは、撤収・出陣・兵の受取は実行しない。

再ログイン、同盟・役職・利用状態の変更、戦役変更では古いスナップショットを失効させる。撤収などの送信前・送信中に始まった取得や、401・403後に遅れて返った取得によって、古い往路が復活しないよう取得世代を照合する。

### 施設を絵札・一覧で管理

城下普請帳に「絵札」と「一覧」の切り替えを追加した。絵札は1頁6施設、一覧は1頁16施設。標準順、レベルが低い順・高い順、必要金銭が少ない順、名前順で並べ替えられる。普請の使用枠と建設済み施設数を上部へまとめ、収支・奉行配置・普請のルールは必要なときに展開できる。

既存の状態フィルターに「資源充足」「奉行未任命」を追加した。「強化候補」は天守の条件を満たす普請中以外の施設、「資源充足」は表示時点で次の増築に必要な資源が揃う施設であり、指令と普請枠の確認は詳細画面で行う。実行ボタンは既存の費用・指令・枠・操作権限の判定を維持する。最高段階に達した施設にも「施設・奉行を確認」を残し、奉行の選択へ進める。

資源の増減後は「最新の資源で更新」を押すと、現在の条件のまま対象施設を再計算できる。更新後もボタンのフォーカスを保持する。毎秒の更新で検索結果の構成を変えないため、一覧を読みながら操作を続けられる。

検索語・分類・状態・並び順・表示形式は端末のブラウザへ保存する。条件をリセットしても並び順と表示形式は維持する。保存領域が利用できない場合も、その画面内での操作を継続できる。これらは表示設定であり、ゲームのセーブやクラウド資産へ書き込まない。

スタッフの施設は既存の共同拠点の投影値と共同普請を使い、任官前から残る個人普請を混在させない。予約が複数ある同一施設は1つの普請枠として数える。

### 最大3名の武将比較

武将名鑑の絵巻、または武将詳細の「比較に追加」から2〜3名を選び、「比較する」で能力・特技・任命状況を並べて確認できる。同一人物は1枠を使い、別ランクを選ぶとその枠の比較ランクを変更する。

比較する能力は選択した絵巻のランクの値。各絵巻の「所持／未所持」と「最高所持ランク」を別々に表示する。未所持の絵巻も比較できるが、比較では獲得・登用・軍団編成・奉行任命を行わない。軍団・奉行が所持する最高ランクを使用する既存仕様は維持する。

比較ボタンは絵巻の詳細ボタンと別の操作として配置し、選択のたびに一覧や肖像を作り直さない。比較表から武将詳細へ移る際など、開いているダイアログ内の操作部が置き換わる場合は有効な閉じる操作へフォーカスを移す。保持された入力欄や別画面の入力からはフォーカスを奪わない。

選択チップの読み上げ名には武将名と選択ランクを含める。キーボードでチップを外す、または選択を解除して操作中のボタンが消えた場合は、残ったチップ、一覧内の表示中の比較ボタン、検索欄の順にフォーカスを移す。検索結果が0件でも、閉じた詳細ダイアログに残るボタンへは戻さない。

全メニューの「武将名鑑」は、前回「武将招集」を開いていても名鑑を直接表示する。招集への専用入口と、武将画面内の名鑑・招集サブタブはそれぞれ選んだ画面を開く。モバイルでは比較の能力表を先に配置し、武将詳細の比較ボタンは本文内から操作できる。

## セーブ互換性とAPI側の修正

### 体力・共通時計の記録がない旧セーブ

旧形式の初回同期でも既存の共通時計移行を適用する。旧保存内の月数をそのままサーバーの維持費基準と比較せず、資源・兵・家臣・工事を保持して共通時間へ基準を合わせる。移行そのものでは過去の収入、維持費、周回報酬を加減しない。既に保存されている未移行データとの比較も、体力・修復・維持費で同じ移行後の基準を使う。

共通時計を持つ保存に対し、時刻のない旧ファイルを再送して巻き戻そうとした場合は `409 CLOCK_ANCHOR_REQUIRED` で拒否する。不正な資源・工事・体力や偽装した役職を含む入力でも、直前の正常なクラウド保存を保持する。本人確認、単一書込端末、保存リビジョン、維持費の権威情報、専用資産の権限検証は既存の条件を使う。

### 旧京都拠点の個人工事

旧京都拠点の私有城郭Lv.63とLv.64への工事を、共同拠点へ投影した後の再保存と工事完了でも維持する。画面の共同御所と個人の旧保存を区別し、個人工事の完了を共有御所のレベル・収入・建設履歴・貢献へ加算しない。再読込での二重完成や解任後の扱いも確認した。

ブラウザとWorkerに配布するエンジンは同じ変更を持つ。新しいセーブ形式やDB移行は追加していない。**復元修正を本番へ反映するにはフロントエンドに加えてAPI Workerの配備が必要**であり、GitHub Pagesだけの更新ではAPI側の処理は変わらない。配備手順は [server/README.md](../server/README.md) を参照する。

## 更新処理と配信量

予定表は既存の移動UIの更新通知を利用し、独自の1秒タイマーを追加しない。移動UIは同じ更新内で取得した移動状態と時計を再利用する。アプリ側の明示的な更新と待機用タイマーが重ならないよう調整し、非表示タブでは待機タイマーを停止して復帰時に更新する。表示更新では移動の到着を確定しない。

配信CSSは既存の構文圧縮に続けて重複宣言などを整理する。ルールの移動、条件の異なるメディアクエリの統合、セレクターの変形、URLの変更、数値の丸めは行わない。`clamp()`を含むfont短縮形は維持する設定とし、固定した依存バージョンで再生成する。

配信量は生成済みの入口6 bundleを測定した。既存の容量上限は変更していない。

| 指標 | 最終測定値 | 既存の上限 |
| --- | --- | --- |
| 入口の6 JS/CSS bundle合計・raw | 2,949,184 B | 2,950,000 B |
| 各bundleを個別gzipした合計 | 844,756 B | 850,000 B |
| v5.3.0からの増減 | raw +47,785 B・gzip +14,378 B | 新機能追加後も既存上限内 |
| ローカルゲート | 66コマンド項目が成功 | 詳細は検証JSON |

画像・音楽・必要時に取得する追加データは入口bundleの容量に含めない。端末の起動秒数、FPS、バッテリー消費の改善率は測定していない。

### 移動表示の処理量

60回の停止中更新を使った回帰計測では、移動状態の読取回数が120回から60回へ、カウントダウン用の文書全体走査が60回から0回へ、変化のないカウントダウン本文の書込が60回から0回へ減った。画面上の表示が変わる更新や新しい行の追加は引き続き反映する。起動時間やFPSの測定結果ではない。

### 最終ブラウザでの操作回帰

qa6では、武将詳細で比較へ追加して閉じた後に検索結果を0件にし、キーボードで「選択を解除」すると検索欄へフォーカスが戻ることを確認した。武将招集→城下町→メニューで「比較」を検索→武将名鑑という経路も、名鑑と比較トレイへ到達した。選択チップの読み上げ名には選んだランクが含まれる。

qa7では、詳細画面の比較表ショートカットが0名・1名のときは `hidden=true` / `display:none` / 幅0、2名のときは表示されることを実ブラウザで確認した。既存のボタン装飾がHTMLのhidden属性を上書きしていた箇所を、限定したCSSで修正した。

### 旧フィクスチャを修正した理由

広い検査で見つかった初期失敗は、基準コミットでも再現して原因を分けた。現在の仕様に追従していなかった期待値・手順を更新し、検証対象の権限や保存保持を弱める変更はしていない。

- `test-sync.mjs` と `test-field-migration.mjs` は、アップロード元の古い `savedAt` と、正規化後の新しい書き出し日時を同一視していた。`Date.now()` と `new Date()` を同じ検査時計へ揃え、確定日時と安定した再読込を確認する形にした。
- 同期の再送には、実際に認証応答から得た共通時計と維持費リビジョンを使う。時刻・権威情報の欠落や不正値を意図した要求は引き続き別ケースとして拒否と保存保持を確認する。
- `test-world-cycles.mjs` の公開DTOの期待値に、既に存在する `playerCityHonors` が抜けていたため補い、通常の城主では空配列であることも確認した。
- `test-sync-integration.mjs` は初回同期で既に付与される共通時計、行軍中に進む防衛側の生産、新戦役の認証済み開始APIに合わせた。同期・紛失防止・二重反映防止の比較は維持した。
- 保存済みの未移行形式を扱う体力検査は、現在の初回アップロードで再現するのではなく、移行前サービスが保存した状態をローカルDBへ用意する形にした。

### 現在の表示上の制約

「資源充足」の対象集合は絞り込みを適用した表示時点で決まる。毎秒の収入・維持費で資源量が変わると表示済み施設のバッジは更新するが、新たな対象施設の出入りは「最新の資源で更新」、全体再描画、絞り込みの再適用で反映する。実行時の費用・指令・枠は詳細の既存判定で確認する。
