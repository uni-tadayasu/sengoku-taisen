# Ver.5.10.1 — 運営の全体BGM配信

## 変更内容

「交流の間」→「運営」→「全体BGM」で、運営権限を持つ領主が全体配信をON／OFFし、ループ／連続再生を切り替えます。初期状態はOFFです。スタッフ・一般プレイヤー・未認証のリクエストでは変更できません。

| 設定 | 動作 |
| --- | --- |
| ON・ループ | 訂正添付された00004.mp3を繰り返す |
| ON・連続 | 00004 → 支度 → 朝活 → 昼活 → 夜活 → 既存16曲を順番に再生し、末尾から00004へ戻る |
| OFF | 各プレイヤーの通常の自動選曲・手動選曲へ戻る |
| 配信中に方式を変更 | 新しい開始時刻を保存し、00004の先頭から新しい方式で始める |

接続中の新版クライアントは約5秒間隔の公開読み取りAPIで状態を確認します。途中参加や非表示からの復帰では、サーバーの開始時刻を基準に現在の曲と再生位置へ合流します。ネットワーク・音源取得・ブラウザによる遅れはあり、サンプル単位の完全同期を保証するものではありません。オフライン端末と旧版は更新・再接続が必要です。

個人の停止、音量0、通話中・非表示中の一時停止、ブラウザの自動再生制限を維持します。運営配信は個人の選曲設定を書き換えません。

2026年11月27日に訂正添付された **00004.mp3** を、再圧縮せず `assets/music/operation-broadcast.mp3` として収録しました。先に添付されたWAVは使っていません。

- サイズ：4,631,901 bytes
- SHA-256：`e49be4d9323bb82de5bb5b7044fedd3a37cba026a1450f2c484c1460c35f1656`
- 48,000 Hz・ステレオ。コンテナ表記202.152秒、実デコード202.12秒。
- 原本とのバイト一致、全体のデコード、プレイリスト先頭と登録時間を確認。
- 音源は必要時に取得。Service Workerの既存のRange／キャッシュ処理を利用。

## サーバーと競合処理

匿名 `GET /api/v1/music` は共有設定だけを読み、ゲーム進行や活動記録を書き込みません。管理APIは認証・運営権限・アカウント利用状態を検証し、revisionと操作受付番号を使って原子的に更新します。同じ設定の再保存・同一操作の再試行では曲を再開始せず、遅れた応答も新しい状態を巻き戻しません。

移行0042は共有状態・操作受付の2テーブルを追加し、既存0000〜0041とプレイヤーデータを変更しません。初期行はOFF・loop・revision 0です。通常BGM20曲の公開カタログは互換性を保ち、放送用カタログにだけ今回の1曲を追加します。

### ブラウザ確認

本番と同じ音楽エンジン・運営UI・訂正MP3を使うローカル検証ページで、実際にボタンを操作して確認しました。本番APIは呼び出していません。

- ONで00004を再生し、ループが選択される。
- 個人停止中に運営の方式を変更しても、個人停止が維持される。
- 連続再生の終端6秒前から参加し、自動で「支度」へ進む。
- OFFで通常の「支度」に戻る。
- 390px幅のiframeでONスイッチと方式選択が収まる。本文の横スクロール幅と表示幅はいずれも373px。

公開後の放送状態はOFFのままにします。今回の検証で実プレイヤーへの試験配信は行っていません。
