# v5.12.0 — 追放と鹿児島城のサブ運営

## 変更目的

BANと分けて、運営がプレイヤーを城から追放し、その領主枠をほかのプレイヤーが選べるようにする。鹿児島城をサブ運営の固定拠点とし、占領不可・勝利報酬あり・家臣受入なしとする。サブ運営は主運営が一人を任命・解雇する。

## 利用手順と結果

| 操作 | 入口 | 結果 |
| --- | --- | --- |
| 領主を追放 | 交流 → 運営 → プレイヤー管理 → 対象 → 追放の内容を確認 | 本人の所属を外し、領主枠を空ける。ほかの家臣は残り、自動昇格しない。 |
| 家臣を追放 | 同上 | 本人だけを除籍し、現在の領主とほかの家臣は維持する。 |
| サブ運営へ任命 | 交流 → 運営 → サブ運営 → 対象を検索 → 任命の内容を確認 | 元の通常城を離れ、個人の資産・武将・育成を保持して鹿児島へ移る。 |
| サブ運営を解雇 | 同画面 → 解雇の内容を確認 | 個人の進行を保持して元の拠点へ戻る。元の通常城が満席なら家臣として復帰する。 |

追放はアカウント停止ではなく、BAN・投稿・購入済み権利を変更しない。追放された本人は拠点を選び直して再開できる。武将の所持・育成と購入済み権利を継承し、資産・兵は開始値を上限として現在残高が少なければその額を使用する。施設・研究・戦役は既存の本拠移転と同じ条件で初期化する。再入城前後とも、追放前の古い戦役で元の所属を復活させることはできない。

サブ運営は単一枠。現在の担当者を解雇してから別の領主を任命する。進軍・派遣中は帰還後に任免する。BAN中でも運営は解雇でき、BANそのものは継続する。サブ運営への任命は、主運営や京都御所の権限を付与しない。

## 鹿児島城の保護

- 鹿児島城は通常の開始城・移転先・家臣入城先から除外し、一般の候補を123城とする。
- CPUの侵攻、通常戦役、共通フィールド、派遣部隊の反撃で占領されない。通常プレイヤーの統一対象は126城とする。
- 共通フィールドの勝利は既存の報酬戦と同じく、金銭・兵糧・木材・石材を各500まで、所持上限の範囲内で付与する。防衛側の兵・資産・武将・施設を変えない。
- 個人のCPU戦役では金銭・兵糧の勝利報酬を付け、所有権の移転・新規駐留・武将獲得を行わない。
- 導入前の一般プレイヤーの鹿児島セーブは、資産・武将・施設などの成長を保持して通常城へ移行する。周期の本拠、評価、地図も同じ移行後の状態を使う。
- 既存の大坂・二条・名古屋を本拠とする正規セーブは、解雇時に記録した元の大城へ復帰できる。通常城への自動移行と、江戸・京都御所・鹿児島の権限制限は維持する。

## 永続化・競合への対応

`0048_player_expulsions.sql` と `0049_deputy_operator.sql` はスキーマ追加のみ。既存移行を変更せず、データの一括削除や本番プレイヤーへの任免を含めない。追放記録、終了済み戦役、任免の受付番号、旧本拠の個人セーブを独立した台帳で管理する。

操作の確認では対象の公開IDと作用を表示する。通信結果が不明な場合は同じ受付番号を保持し、再送を一度だけ確定する。保存revision、現在の運営、スタッフ任期、サブ運営任期、BAN世代、追放世代、所属城と領主期を確定時にも照合する。失敗時は受付記録と所属・セーブ変更をまとめてロールバックする。

役職変更時は旧writerを失効させ、端末は正規スナップショットを受け取るまで保存を停止する。追放の `save:null` は初回未保存と区別し、旧データをアップロードせずに再入城へ案内する。同じ追放回の再入城記録はページを開き直しても保持する。

D1の上限に合わせ、役職の確定条件は同じユーザーIDを相関参照してバインドを共有する。検証した54のバックエンドスイートで最大97、100個を超えるSQLは0件だった。

### 実ブラウザーの操作確認

本番と同じ追放・サブ運営のJS/CSSを、実プレイヤーを使わないメモリー内APIの画面で確認した。デスクトップで対象検索→任命確認→任命→解雇と追放の完了表示、390px幅で任免の確認・取消・確定と追放確認を操作した。

390px幅では任命確認欄が見えている範囲の下へ追加される問題を検出したため、確認欄まで最小限スクロールし、取消・完了後は操作元へフォーカスを戻すよう修正した。再確認では確認欄とボタンがスクロール領域に収まり、横にはみ出さず、実行・取消を操作できた。別の画面へ移った後にフォーカスを奪わないことも自動テストで検証した。サブ運営UIは12シナリオ、管理・通信統合は26検査成功。
