# v5.22.0 — 軽量化・占領領地・本人の京都御所表示

検証日: 2026-11-28（日本時間）。基準: main `d601ca83c0fbc19f156f2414ade24407c8c6652a`（v5.21.0）。

## 依頼に対応した表示

- 共通フィールドに、各プレイヤーが現在の周回で占領している一般城を追加。領主IDと城IDの組で扱い、同じ城に複数人の領地がある場合も個別に選択できる。
- 一覧の「自分の領地」「占領領地」で絞り込み。新しく追加した一般占領地は閲覧専用で、攻撃・占領能力や支拠点を付与しない。
- 京都御所を共同普請できる**閲覧者本人**に、京都御所を共同領地として追加。本拠は一般城のまま維持する。「京都御所を見る」→「京都御所を共同普請」で既存の共同普請画面を開く。
- 本人の現在の任命・役職をサーバーで確認し、応答作成中の資格変更も再検査する。他の一般城の役職者を新しく公開名簿に追加する機能ではない。従来の京都御所所属者の公開本拠は引き続き表示する。
- 一般城の公開領主名は入城台帳を正とし、個人戦役の占領地を排他的な公開城主と混同しない。

## 負荷を減らした処理

### クライアント

1. 領主評価は全階級の武将オブジェクトを毎回作らず、階級数の集計と編成・奉行に必要な能力のみ参照する。
2. 所有城数・維持費・隣接判定で、不要な城の耐久・装飾モデルを生成しない。
3. 同期は分離されたオブジェクトスナップショットを直接作り、JSON文字列化後に再パースする処理を省く。自動保存は余白を省いた同一形式のJSONを使い、手動ダウンロードは従来の読みやすい形式を維持する。
4. 軍師の提案は一度の同期処理内で軍団の戦力を一度だけ計算。次の提案では階級・体力・編成を再取得し、永続キャッシュによる古い戦力の流用を避ける。
5. 装飾アニメーションは現在見えている候補だけを再判定。同じ可視状態の通知や画像読込完了だけのクラス変化を省く。画像装飾のキューも一フレームにまとめ、全候補同士の包含比較を親要素の走査に置き換える。
6. 共通フィールドの検索・絞り込み・4件単位の一覧ページ送りでは地図と詳細を再構築しない。地図のドラッグ・ズームでは既存のマーカー表示キャッシュを使い、データ取得時・選択変更時には更新する。

### サーバー

- 所有者名の読み取りに `GET /api/v1/field?view=owners&limit=100` を追加。通常の名前表示では全セーブの正規化、防御力計算、武将体力や使わない公職表示の取得を省く。
- 詳細フィールドは1ページ25人をクライアントから要求。各人の本拠防御計算を再利用し、追加の閲覧専用領地に戦闘計算を行わない。援軍集計も取得ページの対象者に限定する。
- セーブ検証用の不変の階級定義を一度構築。所持武将・階級の検査はその検証内の集合を使う。
- 同じWorkerの短時間のポーリングに対する背景の進軍・通知処理を1秒単位にまとめる。DB側の実行制限、権限照合、資源や合戦の確定条件は維持し、失敗時は次の要求で再試行できる。

## 固定条件による計測

本番の利用者データや実プレイヤーへの負荷試験を使わず、Node v24.22.3とローカルSQLiteの固定データで測定した。処理単体・データ量の比較であり、ゲーム全体のFPS、実回線の応答速度、同時接続可能人数の保証ではない。

| 処理 | 改修前 | 改修後 | 減少率 |
|---|---:|---:|---:|
| 軍師の提案1回 | 20.490 ms | 3.354 ms | 83.6% |
| 同期用スナップショット作成 | 0.819 ms | 0.277 ms | 66.2% |
| 任務状況の読み取り | 0.094 ms | 0.021 ms | 77.2% |
| 隣接する攻略対象の取得 | 0.050 ms | 0.023 ms | 54.5% |
| 自動保存のJSON容量 | 86,040 B | 60,397 B | 29.8% |

評価・収入・同期・任務は256武将、2,047階級、100城、64施設と奉行の固定状態、7試行×400回の中央値。軍師提案は256武将、2,048階級、軍団3人、候補128件、20回ウォームアップ後の7試行×50回の中央値。軍師提案の階級集合取得は132回から1回、体力参照は396回から3回へ減少し、候補数は同じ128件。

所有者表示は80人・161拠点で比較した。新旧リリース全体の測定ではなく、従来クライアントが利用していた詳細取得と、今回の専用取得との比較である。

| 所有者表示用の取得 | 詳細取得 | 所有者専用 |
|---|---:|---:|
| JSON応答容量（未圧縮） | 206,058 B | 37,249 B |
| SQL数 | 20 | 10 |
| ローカル処理時間（3回中央値） | 190.5 ms | 6.1 ms |
| 同じ条件の所有者表示 | 161件 | 161件 |

装飾の固定DOM試験では、960件の既存候補に2件が可視になった際の適格性再検査が962回から2回へ減少。600組の親子要素を予約した場合、候補同士の `contains` 比較は539,700回から0回となり、親をたどる方式に変更した。アニメーションの同時上限64件／タッチ端末40件は維持している。

100件の同時ポーリングを一つのWorkerで発生させたローカル試験では、背景タスク登録、進軍tickの書き込み試行、幕府承認の期限走査は各1回。失敗時の即時再試行も確認した。

## 配信量と互換性

初期バンドルは約3.86 MB、gzip約1.066 MB。今回の領地・京都御所の操作追加により、v5.21.0から約0.12%増えている。軽量化の主な成果は繰り返し計算・不要描画・所有者取得の通信量の削減で、初回ダウンロードが縮小したとの主張はしない。新しい画像・フォント・ランタイム依存は追加していない。実測値と小さい上限余裕は `tests/test-asset-budget.cjs` で管理する。

`engine.js` と `server/game-engine.js` は同一内容。保存スキーマ、手動セーブの形式、既存の合戦ルールを維持する。DBマイグレーションは不要。サーバーの追加APIは従来クライアントと互換で、APIを先に配信してからフロントエンドを更新できる。
