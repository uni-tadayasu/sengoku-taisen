# v5.12.1 — 追放・BAN後の領主名の再利用

## 修正内容

追放後に再入城を待つアカウントやBAN中のアカウントが、`users.name_key` の一意制約によって以前の領主名を確保し続ける問題を修正した。アカウントは不変の公開IDで保持し、名前の予約だけを解放する。

- 新しい追放・BANでは、処分と同じトランザクションで予約を解放する。
- 過去の処分で残った予約は、登録・改名・復帰でその名前を要求したとき、同じ取得トランザクション内で解放する。通常プレイヤーや解除・再入城済みの名前は対象外。
- 処分済みの名前で新規登録しても、以前の認証、役職、セーブ、購入、フレンド関係は引き継がれない。
- BAN解除・再入城では空いている名前を指定する。前の名前が他者に使われていれば `NAME_TAKEN` を返し、処分・所属・セーブ・受付を変更しない。
- BAN解除の確認画面と再入城画面に名前欄を追加した。確定的な重複エラーでは入力を保持して再編集でき、応答不明の場合は同じ受付番号と名前で結果を確認する。
- 追放中のプロフィール編集は名前を予約し直さない。古いタブによる書き込みでも、DBトリガーが予約の復活を防ぐ。

## 既存データと配置

0050はスキーマ追加だけで、ユーザー行の一括更新・削除はしない。既存の処分データへの補正は一意索引で要求された名前を限定し、成功する取得処理と同じトランザクションに含める。名前の正規化規則、通常名と同盟名の重複防止、アカウント世代・操作受付のガードを維持する。サーバーを先に配置し、公開APIのバージョンと機能を確認してからブラウザーを更新する。
