# Ver.5.23.1 検証記録

## 対象

- PCの左メニュー（高さ960px以下）で、各画面への移動ボタンの表示領域を確保。
- 左メニューで、現在の画面の項目が表示範囲外にあるときの自動表示。
- タイトルの「城を選んで始める」が、BGMの準備中に最初のクリックを受け付けない不具合。
- 位階の紋章の画像、技術研究の段階表示の読み上げ、「すべてのメニュー」の見出しの折り返し。
- 対象別CIの外に残っていた回帰テスト23件の更新と、全テストを実行するCIの追加。

APIとDBは変更していない。サーバー側の変更はテストのみで、配備済みのAPI 5.23.0のまま動作する。

## 不具合の原因と修正

### タイトルの最初のクリック

ブラウザの自動再生制限でBGMが待機中のとき、マウスの押下（pointerdown）でBGMを開始していた。開始と同時にBGMの表示（「再生待機」→「読込中」、「BGMを再生」ボタンと案内文の非表示）が変わり、操作欄が縮む。高さ740px以下の横長ウィンドウでは開始ボタンを含む欄が縦中央に再配置され、押下中にボタンが42px移動した。押下と解放の位置が異なる要素になるため、クリックは周囲のパネルへ送られ、ゲームに入れなかった。

BGMの開始をタッチと同じく完了したクリック・キー入力に揃えた。クリックの対象が確定してから表示が変わるため、ボタンは押下中に動かない。

| ウィンドウ | 修正前 | 修正後 |
|---|---|---|
| 800×600 | 最初のクリックが無効（ボタンが42px移動） | 開始 |
| 960×700 | 最初のクリックが無効（ボタンが42px移動） | 開始 |
| 1024×768〜1920×1080、1280×600 | 開始 | 開始 |
| スマホ・タブレット（タッチ6種） | 開始 | 開始 |

### PCの左メニュー

高さ761px以上では、メニュー下部の6ボタン（タイトルへ・ヒント・有料版・保存設定・領域を調整・更新を確認）と版表示が324pxを占め、移動ボタンの欄は最小値80pxまで縮んでいた。1366×768では移動先が「城下町」1項目しか見えなかった。高さ960px以下では下部を2列の縦型ボタンにまとめ（185px）、「すべてのメニュー」の高さも詰めた。

| ウィンドウ | 移動ボタン欄（修正前） | 修正後 |
|---|---:|---:|
| 1366×768 | 80px（1項目） | 187px（約4項目） |
| 1440×900 | 150px（約3項目） | 319px（約7項目） |
| 1280×720 | 288px（メニュー全体をスクロール） | 288px（下部を短縮） |
| 1920×1080 | 350px | 350px（変更なし） |

メニューの欄はスクロールできるが、地図や指揮台から別の画面へ移ったとき、現在の項目が範囲外のまま残っていた。スマホの横並びメニューと同じ規則で、画面が変わったときだけ現在の項目を縦方向に表示する。定期更新では位置を戻さない。1366×768の12画面すべてで、現在の項目が表示範囲に入ることを確認した。

幅1400px以上では「Ctrl K」の表示が見出しの幅を奪い、「すべての／メニュー」と折り返していた。ショートカット表示を説明文の行の右端へ移し、見出しを1行に保つ。

### 表示と読み上げ

- 位階の紋章が旧版のファビコン（20261127）を参照していた。サイト情報の現在の小型ファビコン（jade版）へ揃え、テストもサイト情報から参照する。
- 技術研究の段階表示は `aria-label` を持つが役割のない `div` で、読み上げられなかった。`role="img"` を付けた（axe-core `aria-prohibited-attr` 8件を解消）。

## 回帰テストの整備

`.github/workflows` の対象別CIに含まれないテストは、仕様変更後も更新されず23件が失敗していた。各差分を実装・更新情報・CI対象のテストと照合し、仕様どおりの変更はテストを更新した。

| 原因 | テスト |
|---|---|
| アプリ関数を抜き出すテスト環境に、京都御所の共同領地用の補助関数（v5.20.0）が未登録 | app-sync、branches-sync、maintenance-sync、trade-bridge ほかブリッジ系8件 |
| 鹿児島城がサブ運営の保護拠点となり、統一目標が126城（v5.12.0） | battle-advisor-engine、hints |
| 制覇地域の継承（v5.23.0）で全国制覇は次周回へ継続 | battle-advisor-engine |
| 拠点勝利報酬の資源50%移転（v5.13.0） | durability、branch-facilities（サーバー） |
| 位階による兵糧の追加生産（v5.10.2）が支拠点の兵糧にも適用 | branch-facilities |
| 奉行から支拠点への転任を明示して許可 | branch-deployments |
| 特殊拠点の専用景観（v5.16.0）、城の所有者と外観の公開 | art-previews、event-residents、public-commander |
| 共同領地の権利 `courtEstate`、官職の区分 `jurisdiction`（v5.15.0、v5.20.0） | clans、staff、recent-logins |
| 共通フィールドの占領領地（v5.22.0） | public-identity |
| 降格を先に検出した京都御所側の保護（409） | branch-sieges |
| 修復記録の検証に合わせた手作りセーブ | branch-deployments（サーバー） |
| 運営・スタッフの公開家名、表示文言・クリック対象の模擬要素 | evaluation-surfaces、recent-logins-ui、hints-bridge |

`server/test-internal-diagnostics.mjs` はNode 22だけSQLiteの実験的機能の警告を1行出す。CIと同じNode 24では成功する。

新しい `tools/run-test-suite.cjs` は `tests/` と `server/` の全テストファイルを個別のプロセスで実行し、失敗したファイルの出力を表示する。`.github/workflows/full-suite.yml` がプルリクエストとmainへの反映ごとに、Node 22でビルド整合と全ブラウザ側テスト、Node 24でWorker APIの全テスト（4並列）を実行する。Playwrightを使う `test-roaming-dom.cjs` は、Playwrightがない環境では成功扱いにせず「SKIP」と表示する。

## 画面確認

APIを遮断し、共通時刻だけを模擬した本番同等のローカル配信で確認した（本番のプレイヤー・API操作はしていない）。

- 12画面 × 320×568・390×844・820×1180・1024×768・1180×820・1366×768：JavaScriptエラー0件、横はみ出し0件。
- 公開ページ10種 × 320・390・1366幅：エラー0件、はみ出し0件、ローカルリンク53件すべて到達。
- axe-core 4.10（WCAG 2.1 A/AA）：12画面・タイトル・開始画面・主要ダイアログで違反0件（タッチ端末の拡大固定は既存の設計で、ゲーム内の文字サイズ設定で補う）。

- 全ボタンの自動操作（1366×768で144回、390×844で145回）でエラー0件。`file://` で開くオフライン版も開始できる。
