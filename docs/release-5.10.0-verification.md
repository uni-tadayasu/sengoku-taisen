## 原子的な保存と復元

- 招集費用、最終獲得、重複50勾玉、使用回数、ログイン報酬、受付番号を同じD1トランザクションで確定します。
- 通信結果が不明な操作は受付番号を保持して再確認します。二度のタップ、再読み込み、端末変更で同じ操作を重ねて付与しません。
- 遅れて届いた前の領主や古いGET応答は、現在の領主・確定済みの結果を上書きしません。
- 再抽選回数とログイン受取はセーブから独立した台帳です。campaign ID変更による回避も検証します。
- 正規の新しい物語を許可し、既知の物語はサーバーが保存した最新状態を基準に復元します。招集結果や勾玉を過去へ戻すバックアップ、未知IDの進行済みセーブの持込みは拒否し、最新クラウド保存の読込みを案内します。
- 返金・支払い取消等は該当支払いの特典を失効させます。失効した再抽選候補は選択できず、最初の候補は選べます。
- 例外的に開いたままの決済から重複支払いが成立した場合、パスは30日を追加し、同月4件目以降のサポーター選択権は次の空き配色月へ割り当てます。

### 売上・継続指標の測定範囲

売上欄は、Stripeの署名付き通知から商品・領主・JPY決済が照合できた全9商品の支払額です。同じ決済を一度だけ集計し、返金・取消・保留等で現在有効でない決済は全額を別枠へ分けます。部分返金の実額、Stripe手数料、精算・入金を反映した純売上ではありません。商品を特定できない除外額も独立表示し、内訳から消しません。

無料／課金別再訪率は、0041導入後に初めて認証済みゲームAPIの成功を観測した接続領主を起点とします。新規登録日の集計ではなく、未接続・オフラインの利用は含みません。起点時の課金区分を固定し、翌日または30日後の丸一日を観測し終えたアカウントだけを分母とします。サポーター更新率は計測開始後に終了した支払済み期間と、7日間の観測猶予を用います。導入前の支払い確認時刻やゲーム活動を推測して埋めません。

実Workerのテスト出力を変更せずに `cleanMetrics` と `metricsMarkup` へ渡し、9商品・金額・無料／課金の母数・未成熟時のnullが受理・描画されることを確認しました。実売上や本番プレイヤーの値を生成した試験ではありません。
