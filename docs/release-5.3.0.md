## 変更と使い方

### 城下町の「領国の指揮台」

本拠タブに、普請・研究の進行と予約、既存の行軍一覧が扱う進軍・帰還、達成済みで報酬未受取の領主任務、本隊の兵数・編成・士気をまとめた。各項目から既存の確認画面へ進める。日次・週次の任務は「今日の任務」で扱い、指揮台の未受取件数とは区別する。

金銭・兵糧の月間差引と赤字の案内を添えた。月替わりの自動減兵に関係する金銭・兵糧と、資材の赤字では説明を分ける。表示モデルは既存の状態を読むだけで、資源・兵数・任務・行軍を進めたり変更したりしない。定期更新はヘッダーで取得した収支を再利用し、変わった文字だけを更新する。

### 上部の資源から収支帳簿へ

金銭・兵糧・木材・石材を押すと、選んだ資源の帳簿を開く。生産、兵の維持費、施設・城の維持費、奉行給与、余剰調整、修復見込み、差引を確認できる。資源タブは左右キー・Home・Endでも切り替えられ、非選択パネルはhidden/inertとなる。

兵数・給与・完成レベルの詳細、収支や修復の仕組みは必要なときに展開できる。生産施設・軍団の見直しへも移動できる。閉じた帳簿では表示更新の走査を省く。共通ダイアログには見出し・説明のARIA参照も付与した。

### ゲーム内メニューと公開ガイドの検索

ゲーム内メニューは機能名の一致を優先し、一致箇所、カテゴリ件数、現在の画面を表示する。「帰還」「移動時間」「修復」「奉行給与」などからも探せる。結果がない場合は条件解除や全カテゴリ検索を案内する。Enterでの移動は候補が一意で実行可能なときに限り、日本語変換中は確定しない。狭い画面・横向きでも結果欄を確保する。

公開ページには共通の「ガイド検索」を追加した。遊び方、引き継ぎ、作品資料、更新情報の61項目を見出し・本文から検索する。検索インデックスは最初に検索を開くまで取得せず、使用後だけ公開アセットとしてオフライン保存する。表示文字列はtextContentで構成し、検索結果のリンク先は同一オリジンに限定する。

矢印・Enter・Escape・検索ショートカット、変換中の操作、結果ゼロ、読込失敗と再試行、閉じた後のフォーカス復帰を確認した。古いIME形式のkeyCode229にも対応し、入力済みの検索欄でもEscape一回で閉じる。

### 画面の読みやすさと文字サイズ

見出し、一覧、フィルター、操作部、数値表示の余白と色を整理した。城下町の標準PCレイアウトでは指揮欄を広げ、保存済みの任意の画面比率を優先する。大きな数値は全桁を残して狭い枠内に表示する。

「保存・設定 → 音・表示 → 文字の大きさ」から「標準／大きめ」を選べる。大きめは本文と説明の文字を拡大し、キャンバスやゲーム全体を拡大変形しない。表示演出とともに端末の表示設定へ保存する。古い演出のみの設定も読め、OSの動きを減らす設定を優先する。ゲームのセーブやアカウント情報へは書き込まない。

奉行を支城の指揮官へ異動するときは、候補と確認文に元の施設名を表示し、元の施設が奉行未任命になることを操作前に案内する。既存の軍団・他支拠点の予約、満員、所有、操作権限の判定を利用する。

### 長時間利用時の不要な処理を抑制

画面切替で切り離した画像の監視を解放し、再使用時に必要な監視を復帰する。古い監視コールバックや、読み込み途中で閉じたダイアログによる寸法測定・画像反映を抑える。閉じた会話画面、文字だけの変更、画像装飾クラスだけの変更で不要なレイアウト再計算を行わない。入力中の文章・選択範囲・メンション・送信状態を保つ。

### 実Service Workerによる旧版からの更新

同じローカルHTTPオリジンでv5.2.0を起動し、配信ファイルをv5.3.0へ切り替えた。新しいworkerがwaitingになった後、実際の「新版を開く」ボタンから新版へ移動し、指揮台の表示、オフライン再読込、旧タブ終了後の新版worker有効化と旧キャッシュ削除を確認した。

一時停止した戦役の状態と、セーブ・音声設定・表示演出・PCレイアウトの4つのlocalStorage値は全段階で文字列単位で一致した。ページ例外0件、外部書き込み0件。外部API通信は遮断し、実ユーザーのデータを使っていない。CDNの公開反映、ログイン済み同期の引継ぎ、音声の実出力はこのローカル更新検査には含まれない。

### 配信容量

ゲーム入口の6つのJavaScript/CSS bundle合計はraw **2,901,399 B**、個別gzip合計 **830,378 B**。上限raw 2,950,000 B、gzip 850,000 Bの両方を通過した。v5.2.0比では新機能によりraw 34,419 B、gzip 9,156 B増えている。画像・音楽・検索開始時に取得する公開インデックスはこの数値に含まれない。端末の起動秒数やFPS改善率は測定していない。

## 互換性と既存課題

ゲームエンジン、セーブ形式、経済計算、到着判定、サーバーの権限・データベースは変更していない。追加のサーバー配備やDB移行は不要。公開検索のキャッシュは対象ファイルを完全一致で限定し、API・認証・セーブ・非公開JSONはキャッシュ対象に加えていない。

広い既存テスト群には、現行DTOの追加フィールド、維持費の権威情報、実時間経過を反映していない旧フィクスチャがある。今回の53コマンドの成功を、リポジトリ全テストの成功とは扱わない。次の互換性課題は基準版から存在し、今回のUI改修とは分けて記録する。

- officerHealth/worldClockを持たない一部の旧形式をサーバーへ直接インポートする検査では500となる。失敗時の保存行の更新はなく、現行ブラウザで正規化・書き出した保存の対照ケースは200となる。
- 旧京都拠点の移行検査では、投影後の施設レベルと旧Lv64工事の不整合により400となる。

詳細な検証一覧は [release-5.3.0-verification.json](release-5.3.0-verification.json) を参照。
